# analytics.orders.orders_daily Table Overview

The `analytics.orders.orders_daily` table is the final target BigQuery table that stores normalized and ingested data sourced from various payment and eCommerce platforms. It is the result of an ETL pipeline that ingests, joins, and normalizes external payment processing and eCommerce logs.

## Lineage and Data Sources

Data for this table is generated by an ETL pipeline that processes information from two primary external sources:
*   **Stripe Payments API**: Provides transaction payment intents, including `payment_intent_id`, `amount_cents`, and `currency`.
*   **Shopify Orders Export**: Supplies store transaction data such as `order_id`, `customer_id`, `total_amount`, and `status`.

## Schema

The `analytics.orders.orders_daily` table includes the following columns, designed to consolidate and normalize transaction information:

*   **`order_id`** (STRING, Primary Key): This column directly maps to the Shopify order identifier, serving as the primary key for the table.
*   **`customer_id`** (STRING): Represents the Shopify customer identifier and can be used to join with the `customers.customer_dim` table for customer dimension data.
*   **`total_amount_usd`** (NUMERIC): The total transaction amount, normalized and converted to United States Dollars (USD).
*   **`payment_status`** (STRING): Indicates the standardized status of the payment, with possible values including `pending`, `paid`, or `refunded`.
*   **`created_at`** (TIMESTAMP): Records the exact time the transaction was processed, stored in UTC.

## Orchestration and Operations

The data pipeline that populates `analytics.orders.orders_daily` is managed with specific operational metadata:

*   **Orchestration**: The pipeline is orchestrated via an Airflow DAG named `orders_daily_v3`.
*   **Execution Schedule**: It runs daily at 03:00 UTC.
*   **Service Level Agreement (SLA)**: The pipeline must complete its execution by 05:00 UTC each day.
*   **Data Platform Owner**: The Data Platform Team (`data-platform@company.example`) is responsible for the technical ownership and maintenance of this data asset.
*   **Business Sponsor**: The Revenue Analytics Team (`revenue-analytics@company.example`) is the primary business sponsor, guiding its analytical use cases.
